# 发布前检查清单

> 适用场景：**每次**推送到 `main`、开启 GitHub Pages、把链接发给别人、或申请公开仓库之前。
> 最近一次执行：2026-10-17 · 结论：**通过**（详见文末审计记录）

---

## 一、三条铁律

1. **先检查，再推送。** 一旦 push 到公开仓库，内容就可能已被爬虫、镜像站、搜索引擎抓走；删掉也收不回来。
2. **不确定就按"会公开"处理。** 私有仓库改公开只需一次点击，但泄露出去的信息无法撤回。
3. **提交历史也算内容。** 不只是当前文件，`git log` 里的作者、邮箱、曾经的提交内容都会公开。

---

## 二、自动检查（已脚本化，不用手点）

```bash
bash scripts/preflight.sh
```

退出码 `0` 才能发布；非 `0` 表示有阻断项。CI 里由 `.github/workflows/pages.yml` 的 `preflight` job 自动执行，检查不过就不会部署。

脚本会阻断或提示以下几类：

| # | 检查组 | 具体内容 |
|---|---|---|
| 1 | 凭证与密钥 | GitHub/OpenAI/AWS/Slack 等令牌、私钥块、JWT；邮箱与手机号 |
| 2 | 本机路径与隐私 | `C:\Users\...`、`/Users/...`、`E:/workbuddy` 等含用户名的绝对路径；`.env`、`.workbuddy/`、`id_rsa`、`*.pem` 是否被误纳入版本库 |
| 3 | 页面运行时安全 | 是否声明 CSP；是否引入外部脚本/样式/iframe；是否有 `fetch`、`XHR`、`WebSocket`、`sendBeacon`、地理位置、cookie 写入；是否有 `eval`/`document.write`；调用麦克风时是否有使用前说明 |
| 4 | 仓库卫生 | 超大文件、必备文件是否齐全、提交邮箱是否为 noreply |

## 三、人工检查（脚本查不出来，必须自己判断）

发布前逐条过一遍，勾选后才推：

- [ ] **仓库可见性**：公开 = 任何人都能看、能下载、能 fork。确认里面没有只给自己看的东西。
- [ ] **教材版权**：本项目词汇与句型取自人教版教材。个人自用没问题；公开传播属于对外发布，风险等级变化。若版权方提出异议需立即调整。
- [ ] **截图与文档**：README 配图、设计文档里有没有出现本机路径、真实姓名、学校班级、孩子照片、聊天记录。
- [ ] **新增依赖**：有没有新加的 CDN、字体、统计脚本、第三方 SDK？每加一个外部资源，隐私面就扩大一层，且破坏"离线可玩"。
- [ ] **新增权限**：有没有新调用摄像头、麦克风、通知、剪贴板、定位、文件读取？每个都要有使用前说明。
- [ ] **本地存储内容**：`localStorage` 里存的是不是仍然只有游戏进度（分数、错题、设置）。一旦开始存姓名、班级、头像，就属于个人信息，规则完全不同。
- [ ] **提交身份**：`git log` 作者是否是 noreply 邮箱或想公开的化名。
- [ ] **链接有效性**：README 里的在线试玩地址、文档链接是否指向真实存在的页面。
- [ ] **儿童相关**：如果使用者是未成年人，不要加入任何要求填写真实信息的表单、上传、社交功能。

## 四、发布操作步骤

```bash
# 1. 检查
bash scripts/preflight.sh

# 2. 看看到底会公开哪些文件（这一步别省）
git status --short
git ls-files

# 3. 提交并推送
git add -A
git commit -m "..."
git push origin main
```

推送后到仓库 **Actions** 页确认 `Security preflight` 与 `Deploy` 两个 job 都绿了。

## 六、已知残余风险（改不掉，只能如实告知）

1. **语音识别的音频去向**：`SpeechRecognition` 由浏览器实现，Chrome 会把音频发到 Google 服务器做识别，Edge 走微软。本游戏自身没有服务器，但这一段链路不受本项目控制。**已在应用内和 README 中明示**。
2. **教材内容版权**：MIT 只覆盖代码。若将来商业化或大规模公开传播，需走"知识点对齐 + 自研内容"或取得授权。
3. **GitHub Pages 是公开托管**：链接一旦分享出去，任何人可访问源码与页面。
4. **Actions 使用版本标签**（`@v4`/`@v5`）而非固定 commit SHA：官方 action 风险很低，但严格供应链安全应改为 SHA 固定。
5. **本机 git 全局配置**：为绕过代理导致的证书吊销检查报错，本机设置了 `http.schannelCheckRevoke=false`。这降低了本机的传输校验强度，属于环境层面的取舍，推送完成后可考虑还原：
   ```bash
   git config --global --unset http.schannelCheckRevoke
   ```
