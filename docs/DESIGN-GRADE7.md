# 七年级上册版本 · 设计方案

> 对应文件 `grade7.html`。六年级版见 [DESIGN.md](DESIGN.md)。

## 一、为什么不是简单换题库

六年级版是 5 关、围绕"认词—听辨—造句—开口"。初一的学习重心变了：

- 词汇从"认识"变成"会拼写、会变形"；
- 语法从零散句型变成**成体系的规则**（be 动词 → 实义动词三单 → There be → 情态动词 → 时态）；
- 考试失分点集中在"会但写错"和"规则记混"。

所以这一版在原有 5 关之间插入了两关：**拼写关**（解决"会认不会写"）和**语法关**（解决"规则记混"）。同时把难度调高：Boss 由 10 题扩到 12 题，单元词汇 16–20 个。

## 二、七关结构与设计意图

| # | 关卡 | 题量 | 题型 | 设计意图 |
|---|---|---|---|---|
| 0 | 单词关 | 8 | 中英互选（交替 cn→en / en→cn） | 快速过一遍词义，建立第一层记忆 |
| 1 | 拼写关 | 8 | 看中文 + 首字母提示 + 长度，点字母块拼写 | 从"再认"跨到"提取"，这是初一期中的主要失分点 |
| 2 | 听力关 | 6 | 3 词 + 3 句，听音选义 | 训练连读和句子节奏，句子比单词更难 |
| 3 | 句型关 | 6 | 3 句排序 + 3 句选词填空 | 语序和固定搭配，填空题优先挖本单元课标词 |
| 4 | 语法关 | 6 | 语法选择 + 语法点标签 + 一句话解析 | 把规则显性化，答对答错都讲一遍 |
| 5 | 跟读关 | 4 | 2 词 + 2 句，语音识别打分 | 输出环节，朗读能暴露发音问题 |
| 6 | Boss 关 | 12 | 上述题型混合 | 混合检索比同类集中练更接近考试状态 |

解锁：前一关 ≥1 星解锁下一关；0–5 关全部 ≥1 星才开 Boss；Boss 通关收集该单元纪念品。单元满星 21。

## 三、两个新关卡的具体实现

### 拼写关

```js
makeSpell(u, w)
// → { type:'spell', cn, answer, letters:[打乱的字母 + 2 个干扰字母], hint:'n 开头 · 共 4 个字母' }
```

- 字母块点击填入答案槽，**填满长度不自动判定**，要按「检查」才判——这是为了留出改错的余地（见下）。
- 三条删改路径，孩子随便用哪条：
  1. 点下面用过的字母块 → 撤销那一个；
  2. 点填字框里的字母（右上角挂着淡红 ×）→ 删掉那一个；
  3. 「⌫ 删一个」按钮 → 删最后一个。PC 上还支持退格键和回车。
- 答错第一次：抖动 + 清空 + 提示首字母和长度，可重来。
- 答错第二次：判错、标红、显示正确拼写和中文，进入错题队列。

**为什么取消"填满自动判"。** 最初是填满即判，看着省事，但 3–4 个字母的短词（`bag`、`book`）几乎没有反悔窗口：点错第一个字母后必须点完剩下几个才判错，孩子会觉得"我明明发现了却改不了"。判断该由孩子自己发起，而不是被长度触发。多按一次「检查」的代价，换来的是"检查一遍再交卷"这个考试习惯——这本身就是该练的东西。

为什么用点击而不是键盘输入：
1. 手机端切英文输入法成本高，会打断节奏；
2. 字母块天然给出"长度"和"构成"的线索，属于 scaffolded retrieval，比裸拼写更适合初一；
3. 干扰字母只加 2 个，保证不能靠试错穷举（10 字母词有 12 个块，全排列不可能）。

### 语法关

```js
grammar: [ [题干, 正确答案, [3 个干扰项], 语法点, 一句话解析], ... ]
```

干扰项不是随机词，而是**针对该语法点的典型错误**：

- `There ___ a book and two pens.` → 干扰项 `are`（就近原则误判）
- `My sister ___ to school by bike.` → 干扰项 `go`（漏三单）、`gos`（变形规则错用）
- `December is the ___ month.` → 干扰项 `twelveth`（序数词拼写陷阱）

反馈框在答对时也显示解析。教学上这是"规则复述"，比只给对错更有效。

## 四、单元划分

教材为《义务教育教科书 英语（Go for it!）》七年级上册 2024 修订版。

- **Starter Unit 1–3 合并为一个"起步营"单元**。三个起步单元各有 8–10 个词，单独做成 7 关会大量重复出题；合并后 20 词、9 句，覆盖问候、教室物品、方位、农场动物，正好是入学第一个月的全部内容。
- Unit 1–7 各成一个单元，每单元 18 词、9 句、8 道语法题（抽 6 道）。

## 五、语法点覆盖

| 单元 | 语法点 |
|---|---|
| Starter | 特殊疑问词、There be 就近原则、this/that/these/those 与 be 动词、be 动词否定、方位介词、不规则复数（sheep/geese） |
| Unit 1 | be 动词搭配、What's 缩写、形容词性物主代词、简略回答不缩写、would like to do、Who 提问 |
| Unit 2 | 名词所有格 's、名词复数、三单（watch→watches / go→goes）、Whose、Does 的简答、助动词后接原形 |
| Unit 3 | There be 主谓一致与就近原则、There be 的简答、方位介词 in/behind、Where 提问、have 与 there be、不可数名词 |
| Unit 4 | because / but 逻辑、be 动词、Why 与 Who 提问、时间介词 on、三单 has |
| Unit 5 | 情态动词 can（后接原形、无三单）、can 的简答、乐器前加 the、三单 wants、be good at |
| Unit 6 | 三单 goes/brushes、do 与 does 提问、at/in 时间介词、doesn't 否定、第一人称原形 |
| Unit 7 | 日期介词 on、month 复数、序数词 first、How old、三单 buys、不可数 juice、twelfth 拼写 |

## 六、数据结构

```js
const BOOK = {
  id: 'pep7a',
  name: '英语（PEP）七年级上册',
  units: [{
    id, no, title, cn, badge, color, c2,
    words:     [[en, cn], ...],              // ≥16 个单词
    sentences: [[en, cn], ...],              // ≥8 句
    grammar:   [[题干, 答案, [干扰], 语法点, 解析], ...]  // ≥6 道
  }]
};
```

关卡生成器与教材数据完全解耦：

```js
const builders = [buildWordLevel, buildSpellLevel, buildListenLevel,
                  buildSentenceLevel, buildGrammarLevel, buildSpeakLevel, buildBoss];
```

关卡数量由 `LEVEL_DEFS.length` 决定，常量 `NLV / BOSS / MAX_STAR` 全部派生，页面里没有写死的"5 关 / 15 星"。要加第 8 关，只需往 `LEVEL_DEFS` 和 `builders` 各加一项。

## 八、自检

`scripts/selftest-grade7.js` 在 Node 里加载页面脚本（stub 掉 DOM），对 8 个单元 × 7 个关卡各生成 3 轮题目，校验：

- 题量是否符合关卡定义；
- 选项是否恰好 4 个且互不重复、正确答案是否在选项内；
- 拼写题字母块是否足以拼出答案（多重集包含关系）；
- 排序题乱序块与答案的词集是否一致；
- 语法题是否有语法点与解析、干扰项是否含正确答案；
- 插画 SVG 标签是否闭合、8 张是否互不相同。

另有一层浏览器端冒烟测试（开发时用，未入库）：依次进入 8×7=56 关，自动答完 400 道题，校验无异常、每关都能拿到三星。

## 九、已知取舍

- 拼写关只做单词，不做短语（`dining hall` 这类含空格的词条会被字母块规则破坏），所以词表刻意只收单词。
- 语法关每题只考一个点，无法覆盖需要跨句判断的语境。
- 干扰项写死在数据里，同单元重复刷会记住答案；这是"教育游戏"而非"题库系统"的取舍——真要防背题，需要按语法点动态生成错误项。
