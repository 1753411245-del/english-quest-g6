# 城堡保卫战 · 塔防模式设计说明

> 定位：在七上的 56 关答题闯关之外，新增一种**用策略玩法承载知识分类判断**的模式。
> 代码位置：`grade7.html` 中所有以 `td` 开头的函数与 `TD_*` 常量。
> 回归工具：`python scripts/smoke-td.py`。

---

## 一、为什么是塔防

最初考虑的是横版动作（4399 上的冒险岛 / 造梦西游那种）。否掉它的理由不是做不出来，而是**认知资源冲突**：

- 动作游戏要求手眼协调，语言加工也要占用同一份注意力。孩子一边躲怪一边读题，要么操作差，要么答得差。
- 竖屏上虚拟摇杆要吃掉底部约四成屏幕，题目区被压得没地方放。
- 孩子会优化"看上去最爽"的目标，而不是"答对"这个目标。

塔防（王国保卫战）的结构恰好相反：**它的乐趣在"选择"，不在"操作"**。在哪儿建塔、建什么塔、先升哪座——每一步都是判断，而英语学习的核心动作也是判断。两者可以同构。

| | 横版动作 | 塔防 |
|---|---|---|
| 认知资源 | 与答题争抢 | 几乎全给答题 |
| 策略深度 | 浅（答对就打一下） | 深（塔位、类型、升级顺序） |
| 内容成本 | 高（怪物动画、地形） | 低（塔与敌人可复用） |
| 输了怪谁 | "我手慢了" | "我塔配错了" |

最后一行最关键：塔防的失败是**可解释、可复盘**的。对学习工具来说，能复盘比痛快重要。

## 二、核心机制

### 1. 敌人 = 一个具体错误

场上每只怪身上写着一个真实的典型错误，答案就在它的题目里：

| 敌人类型 | 身上的标签 | 答对后变成 | 标签来源 |
|---|---|---|---|
| 词汇怪 | 中文词（如「地图」） | 对应英文 | 题干的 prompt |
| 拼写怪 | 拼错的词（如 `freind`） | 正确拼写 | 把答案的相邻字母交换 |
| 听力怪 | `???` | 听到的英文 | 答对才揭晓 |
| 语法怪 | 错误词（如 `be`） | 正确答案 | 题干挖空处填一个干扰项 |

答对的瞬间，标签从错误**改成正确并转绿**，敌人随即消散。这个演出是整个模式的支点——孩子打掉十只怪，就是亲眼修正了十个错误，比看到"答对了"有冲击力得多。

拼写怪的错法是交换相邻字母，正好命中学生最常见的拼写错误类型（`friend → freind`）。

### 2. 只有同类型的塔打得动

这是硬约束，也是"布防即判断"成立的前提：

- 词汇塔 ↔ 词汇怪
- 拼写塔 ↔ 拼写怪
- 听力塔 ↔ 听力怪
- 语法塔 ↔ 语法怪

类型不匹配的塔面对敌人**完全无效**。所以孩子必须先认出来的是哪一类错误，才能调动正确的资源。横版动作给不了这一步。

### 3. 金币永远不够

初始 130 金，四座塔全建要 255 金，杀敌 18 金/只、波次奖励 25 金。第一波只够建两座。

**资源充足时没有取舍，没有取舍就没有策略。** 如果答对就必赢，塔就只是装饰，这个模式会退化成套壳答题。这是它最大的风险，必须靠数值守住。

### 4. 节奏由答题驱动

敌人移动到某座匹配塔的射程内就**全局暂停并出题**，不设倒计时。所以不会出现"还没想完就被打死"，答对与否是推进游戏的唯一变量。

每只敌人对每座塔只有一次被考查的机会（`enemy.tried[slot]` 标记），避免同一个塔反复出题。

## 三、关卡数据

一个战场就是 `TD_MAPS` 里的一个对象：

```js
{
  id:'u1-m1', uid:'u1',          // uid 决定用哪个单元的题库
  no:'第 1 战场', name:'初次交锋',
  gold:130, lives:3,
  path:[[318,64],[250,64],[250,124],[160,124],[160,64],[58,64]],  // 敌人行进折线
  slots:[[286,96],[286,32],[206,94],[200,148],[110,96],[110,32]],  // 可建塔的位置
  waves:[
    { hint:'两只词汇怪，先建一座词汇塔', kinds:['word','word'] },
    // ...
  ]
}
```

坐标系固定为 `viewBox="0 0 320 180"`。路径与塔位都在这个坐标系里画，改布局只要改这两组点。

**布防阶段会预告下一波的构成**（`hint`），这是让玩家做分类判断的关键信息，不要省略。

### 数值

| 项目 | 值 | 位置 |
|---|---|---|
| 塔价 | 词 50 / 拼 60 / 听 70 / 法 75 | `TD_TOWERS[*].cost` |
| 升级 | Lv2 55 金，Lv3 80 金 | `TD_UP` |
| 射程 | 词 40 / 拼 36 / 听 44 / 法 38 | `TD_TOWERS[*].range` |
| 杀敌 | +18 金 | `TD_KILL_GOLD` |
| 波次奖励 | +25 金 | `TD_WAVE_GOLD` |
| 敌速 | 每秒走 3% 路径 | `TD_SPEED` |
| 答错惩罚 | 该塔冷却 5 秒 | `tdResolve()` |

## 四、实现要点

- **场景用 SVG，题目用 DOM**。角色、路径、塔、敌人都在一个固定 viewBox 的 SVG 里，靠 `transform: translate()` 移动；题目面板是普通 DOM，中文排版交给浏览器，比在 Canvas 里画文字省事得多。
- **不做整屏重绘**。敌人和塔的 SVG 元素创建后持久保留，每帧只更新 `transform`，保证移动连续。元素引用存在 `B.els` 里，`render()` 后清空重建。
- **状态与答题模式完全隔离**。战斗状态用独立的 `B`，不碰原来的 `G`；`render()` 只新增两个分支，原有七个关卡的分支一行没动。存档用同一个 localStorage 键加 `td` 子对象（`S.td`）。
- **`B` 是 `let` 声明，不挂在 `window` 上**，所以内联 `onclick` 里不能直接写 `B.xxx`，必须调用函数。踩过这个坑，已在 `tdReplay()` 修正。

## 五、扩展新战场

1. 在 `TD_MAPS` 里加一个对象，`uid` 指向 `BOOK.units` 里已有的单元。
2. 设计 `path`（折线）和 `slots`（塔位）。**塔位要保证该类型敌人的整条路径都有覆盖**，否则会出现"建了塔也拦不住"的死角。
3. 波次由浅入深：先单一类型教机制，再混入第二、第三类型。最后一波的类型配比要逼玩家提前建好所有需要的塔。
4. 跑 `python scripts/smoke-td.py` 确认能通关。

---

## 六、已知限制

- 目前只有 U1 一个战场（4 波 14 只怪、约 14 题）。扩展到 8 个单元需要逐个设计路径与塔位。
- 塔的升级只影响标签显示和题目难度档，**没有做伤害数值差异**——因为每只怪血量固定为 1，答对即消灭。等级的实际意义偏弱，后续可以让高级塔一次打多只、或降低出题频率。
- 没有实现射程可视化。点塔时应该显示覆盖范围，帮助孩子判断该建在哪。
- 拼写怪的错法只做相邻字母交换，覆盖不到"漏字母""多字母"等其他错误类型。
- 失败的敌人会进全局错题本（`S.wrong`），但还没有做"错题训练营"这个专门节点。
