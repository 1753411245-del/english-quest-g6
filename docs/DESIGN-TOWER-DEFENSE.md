# 城堡保卫战 · 塔防模式设计说明

> 定位：在七上的 56 关答题闯关之外，新增一种**用策略玩法承载知识分类判断**的模式。
> 代码位置：`grade7.html` 中所有以 `td` 开头的函数与 `TD_*` 常量。
> 回归工具：`python scripts/smoke-td.py`。

---

## 一、为什么是塔防

最初考虑的是横版动作（4399 上的冒险岛 / 造梦西游那种）。否掉它的理由不是做不出来，而是**认知资源冲突**：

- 动作游戏要求手眼协调，语言加工也要占用同一份注意力。孩子一边躲怪一边读题，要么操作差，要么答得差。
- 竖屏上虚拟摇杆要吃掉底部约四成屏幕，题目区被压得没地方放。
- 孩子会优化"看上去最爽"的目标，而不是"答对"这个目标。

塔防（王国保卫战）的结构恰好相反：**它的乐趣在"选择"，不在"操作"**。在哪儿建塔、建什么塔、先升哪座——每一步都是判断，而英语学习的核心动作也是判断。两者可以同构。

| | 横版动作 | 塔防 |
|---|---|---|
| 认知资源 | 与答题争抢 | 几乎全给答题 |
| 策略深度 | 浅（答对就打一下） | 深（塔位、类型、升级顺序） |
| 内容成本 | 高（怪物动画、地形） | 低（塔与敌人可复用） |
| 输了怪谁 | "我手慢了" | "我塔配错了" |

最后一行最关键：塔防的失败是**可解释、可复盘**的。对学习工具来说，能复盘比痛快重要。

## 二、核心机制

### 1. 敌人 = 一个具体错误

场上每只怪身上写着一个真实的典型错误，答案就在它的题目里：

| 敌人类型 | 身上的标签 | 答对后变成 | 标签来源 |
|---|---|---|---|
| 词汇怪 | 中文词（如「地图」） | 对应英文 | 题干的 prompt |
| 拼写怪 | 拼错的词（如 `freind`） | 正确拼写 | 把答案的相邻字母交换 |
| 听力怪 | `???` | 听到的英文 | 答对才揭晓 |
| 语法怪 | 错误词（如 `be`） | 正确答案 | 题干挖空处填一个干扰项 |

答对的瞬间，标签从错误**改成正确并转绿**，敌人随即消散。这个演出是整个模式的支点——孩子打掉十只怪，就是亲眼修正了十个错误，比看到"答对了"有冲击力得多。

拼写怪的错法是交换相邻字母，正好命中学生最常见的拼写错误类型（`friend → freind`）。

### 2. 只有同类型的塔打得动

这是硬约束，也是"布防即判断"成立的前提：

- 词汇塔 ↔ 词汇怪
- 拼写塔 ↔ 拼写怪
- 听力塔 ↔ 听力怪
- 语法塔 ↔ 语法怪

类型不匹配的塔面对敌人**完全无效**。所以孩子必须先认出来的是哪一类错误，才能调动正确的资源。横版动作给不了这一步。

### 3. 金币不宽裕，但可以拆塔挽回

初始 150 金，四座塔全建要 255 金，杀敌 20 金/只、波次奖励 30 金。第一波只够建两座。

**资源充足时没有取舍，没有取舍就没有策略。** 如果答对就必赢，塔就只是装饰，这个模式会退化成套壳答题。数值上必须守住这条线。

但"钱紧"不能变成"建错了就完了"。所以补齐两条退路：

- **拆塔返还累计算投入的 50%**（`TD_SELL_RATE`）。升级过的塔按"塔价 + 已花升级费"一起算，拆掉立刻退回空位。
- **塔位从 6 个加到 9 个**。塔位多不等于能建满（钱不够），但给了"这一波建哪儿、下一波换哪儿"的空间。

拆塔的关键不在退钱，在于**让"改主意"变得便宜**。塔防的策略本来是"看下一波预告 → 决定建什么"，如果改主意要付出全部代价，孩子就只能硬扛。

### 4. 节奏由答题驱动，但战斗永不暂停

这是这一版改动最大的地方。早期实现是"敌人走到射程内 → 全局暂停 → 出题 → 答完继续"，问题很明显：**画面走走停停，一场战斗被切成十几段静帧**。

现在改成：

- **敌人一直走，从不停止。** 被塔锁定时会减速，但不会站着等。
- **答完一题自动接下一题**，没有"下一题"按钮，也不需要点继续。
- **答案高亮保留到下一题出现**。答完立刻清空面板会闪一下，所以故意让正确答案的绿色停在那儿，直到下一道题替换它。
- **答题时也能建塔、拆塔**。早期版本在答题期间禁用了塔操作，那样"边打边补"就无从谈起。

减速系数是有教学含义的：拼写题要点一串字母块，比选择题慢，所以拼写题的敌人被拖到 40% 速度，其他题型 60%（`TD_SLOW` / `TD_SLOW_SPELL`）。

答错不会直接放走整只怪——**它挡下这一击，换一个错误继续冲**，0.7 秒后可以再打。这样答错是"多花时间"，不是"直接判死"。

每只敌人对每座塔只有一次被考查的机会（`enemy.tried[slot]`），避免同一座塔无限缠着同一只怪。

### 5. 锁定环：让"正在被瞄准"看得见

被瞄准的敌身上套一圈流动虚线，颜色就是那座塔的颜色。原本想用"塔到敌人的瞄准线"，但塔和路离得近，线太短、又会被敌人标签的描边盖住，实际看不见——换成目标身上的环，远近都成立。

开火另有弹道线（塔 → 敌人）和命中波纹，答对瞬间才出现，所以平时不干扰视线。

## 三、关卡数据

一个战场就是 `TD_MAPS` 里的一个对象：

```js
{
  id:'u1-m1', uid:'u1',          // uid 决定用哪个单元的题库
  no:'第 1 战场', name:'初次交锋',
  gold:150, lives:3,
  path:[[318,64],[250,64],[250,124],[160,124],[160,64],[58,64]],  // 敌人行进折线
  slots:[                                                          // 9 个可建塔的位置
    [288,34],[288,94],[222,94],[222,152],
    [186,34],[134,94],[134,34],[96,34],[76,94]
  ],
  waves:[
    { hint:'两只词汇怪，先建一座词汇塔', kinds:['word','word'] },
    // ...
  ]
}
```

坐标系固定为 `viewBox="0 0 320 180"`。路径与塔位都在这个坐标系里画，改布局只要改这两组点。
塔位圆半径 12、路宽 19，**塔位中心距路面至少 28 个单位**，否则塔会压在路上。

**布防阶段会预告下一波的构成**（`hint`），这是让玩家做分类判断的关键信息，不要省略。

### 数值

| 项目 | 值 | 位置 |
|---|---|---|
| 初始金币 | 150 | `TD_MAPS[*].gold` |
| 塔价 | 词 50 / 拼 60 / 听 70 / 法 75 | `TD_TOWERS[*].cost` |
| 升级 | Lv2 55 金，Lv3 80 金 | `TD_UP` |
| 射程 | 词 46 / 拼 42 / 听 50 / 法 44 | `TD_TOWERS[*].range` |
| 杀敌 | +20 金 | `TD_KILL_GOLD` |
| 波次奖励 | +30 金 | `TD_WAVE_GOLD` |
| 拆塔返还 | 累计投入的 50% | `TD_SELL_RATE` |
| 敌速 | 每秒走 1.6% 路径（全程约 63 秒） | `TD_SPEED` |
| 锁定减速 | 普通 60%，拼写题 40% | `TD_SLOW` / `TD_SLOW_SPELL` |
| 出题间隔 | 答对 0.4 秒 / 答错 0.95 秒 | `TD_GAP_OK` / `TD_GAP_NO` |
| 同波出场间隔 | 1.6 秒 | `TD_SPAWN_GAP` |

**节奏的底线是"敌人在射程里停留的时间 ≥ 一顿思考 + 一次作答"。** 射程 46、塔距路 30 时，敌人在射程内的路径长约 70 单位（占全程 18%），按 1.6% 速度约 11.5 秒，锁定减速后约 19 秒。

`python scripts/pace-td.py` 就是用来卡这条线的：它按 60fps 推进真实时间，分别模拟每道题思考 2/3/4/5/6 秒，断言都能零漏怪通关。改 `TD_SPEED`、射程或题目耗时后必须重跑。

## 四、美术：古罗马要塞

视觉方向参照《王国保卫战》：手绘感、粗深色描边、饱和的暖色地块、一眼能叫出名字的剪影。

### 为什么不是"随便画好看点"

这个模式要靠画面替三件事说话，美术必须服务于它们：

1. **敌我类型**要能扫一眼分开——所以敌人整个身体用该题型的颜色，塔也用同一个颜色系。
2. **"错误"必须是可读的实体**——所以敌人的错误不放在屏幕角落，而是写在它头顶一块小羊皮纸上，跟着它移动。
3. **纠错要看得见**——答对瞬间那块羊皮纸从米白转成绿色，文字换成正确形式。

第 3 条是整个模式的支点，任何"省事"的改法（只弹一个"答对了"）都会让这个模式退化成套壳答题。

### 配色

全部颜色收敛到五种，避免画面花：

| 用途 | 色值 |
|---|---|
| 草地（径向渐变） | `#bed581` → `#8aa64f` |
| 铺石路 | 路基 `#6f5c3d` / 路面 `#ddcaa2` / 石缝 `#c1a97c` |
| 石灰岩（墙、塔） | `#ecdcbb`，暗部 `#d6c29a` |
| 赤陶（旗、屋顶、按钮） | `#b5523a` |
| 青铜（檐口、金线、火把） | `#c99a3f` |
| 统一描边 | `#5e4a30`（深褐，不用纯黑） |

四种塔的色相刻意避开草绿：蓝 `#3f6ba8`（词）/ 青 `#1f7f8c`（拼）/ 紫 `#7a4a9e`（听）/ 赭 `#bf6a28`（法）。

### 靠剪影区分塔，不靠颜色

20 像素的方块上，颜色相近就会糊成一片。所以四种塔给了四个轮廓完全不同的建筑：

| 塔 | 造型 | 记忆点 |
|---|---|---|
| 词汇塔 | 方塔 + 城垛 + 旗杆 | 平的、带齿 |
| 拼写塔 | 圆塔身 + 穹顶 | 圆的、有球顶 |
| 听力塔 | 哨塔 + 尖顶 + 檐下铜钟 | 尖的 |
| 语法塔 | 台阶 + 立柱 + 山花 | 神殿正立面 |

中间统一挂一块盾徽写题型字——颜色、轮廓、文字三重冗余，认错的可能性很低。

### 等级靠外观长出来

塔升到 Lv2 挂一面小旗，Lv3 两面旗加一道金线。没有用数字徽章：直径 4 像素的圆圈里写 "2"，在手机屏上根本看不清。孩子看塔"变得更气派了"就够了，具体等级点开面板有文字。

### 布局约束

场景坐标系固定 `viewBox="0 0 320 180"`。装饰物（柏树、灌木、碎石、断柱、草丛）的位置是写死的，**必须避开路面（半宽约 10）和每个塔位（半径 16）**，否则会出现"树长在路上"或"塔从树里钻出来"。加装饰前先在纸上按坐标排一遍。

`path` 的终点从 58 移到 46：城门拱洞在 x=19–41，路要伸进拱洞才像"进了城堡"。敌人走到 pos=1 时正好站在门洞里，随即淡出。

### 动效

旗帜飘动（`tdFlutter`）、门口火把跳动（`tdFlame`）、锁定环流动（`tdLockFlow`）。都走 CSS 动画，不占 JS 帧循环。`prefers-reduced-motion` 下全部关闭。

### 不用 Canvas 的理由

场上同时只有 1 座城堡、9 座塔、几只怪、几十个装饰，全是静态图形，CSS/SVG 完全够，还能自动适配高像素屏。用 Canvas 得自己处理 DPR、字体、命中测试，这个规模不划算，而且会和现有 DOM 题目面板脱节。

## 五、实现要点

- **场景用 SVG，题目用 DOM**。角色、路径、塔、敌人都在一个固定 viewBox 的 SVG 里，靠 `transform: translate()` 移动；题目面板是普通 DOM，中文排版交给浏览器，比在 Canvas 里画文字省事得多。
- **不做整屏重绘**。敌人和塔的 SVG 元素创建后持久保留，每帧只更新 `transform`，保证移动连续。元素引用存在 `B.els` 里。塔升级时按 `data-lv` 比对，变了才重建（重画等级与旗帜）。
- **所有图形都是代码画的**。`tdTowerArt(kind, lv)`、`tdEnemyArt(kind, label, fixed)`、`tdCastle()`、`tdCypress()` 一类小函数各返回一段 SVG 字符串，没有一张位图，也没有外部字体。改美术只改这些函数。
- **敌人的"已修正"要能被重建**。`tdSetEnemyLabel()` 改的是已经存在的 DOM，如果这只怪还没被画到屏幕上就被答掉了（首帧），改标签会落空。所以 `tdMarkFixed()` 同时给敌人打 `e.fixed = true`，`tdPaint()` 新建元素时按这个标记直接画成绿色正确形式。
- **空塔位用 `display` 控制，不删元素**。拆塔后要能立刻恢复成虚线圆圈，删了就得重画整张 SVG。
- **HUD 必须每帧同步**。`tdHud()` 只在 `render()` 时算一次，而金币和生命是逐帧变的。早期版本漏了这步，金币涨了界面上看不到。现在 `tdFrame()` 末尾调 `tdHudSync()`，用 `key` 比对，只有真的变了才重绘，金涨/掉血各带一个短动画。
- **面板按状态叠加，不互相覆盖**。`tdPanelHTML()` 在战斗阶段先输出题目（或"等待目标"），再把塔操作面板追加在后面，所以点塔不会把正在答的题吞掉。
- **状态与答题模式完全隔离**。战斗状态用独立的 `B`，不碰原来的 `G`；`render()` 只新增两个分支，原有七个关卡的分支一行没动。存档用同一个 localStorage 键加 `td` 子对象（`S.td`）。
- **`B` 是 `let` 声明，不挂在 `window` 上**，所以内联 `onclick` 里不能直接写 `B.xxx`，必须调用函数。踩过这个坑，已在 `tdReplay()` 修正。

## 六、扩展新战场

1. 在 `TD_MAPS` 里加一个对象，`uid` 指向 `BOOK.units` 里已有的单元。
2. 设计 `path`（折线）和 `slots`（塔位）。**塔位要保证该类型敌人的整条路径都有覆盖**，否则会出现"建了塔也拦不住"的死角。塔位中心距路面保持 28 个单位以上。
3. 波次由浅入深：先单一类型教机制，再混入第二、第三类型。最后一波的类型配比要逼玩家提前建好所有需要的塔。
4. 跑 `python scripts/smoke-td.py` 和 `python scripts/pace-td.py` 确认能通关且节奏不逼人。

## 七、已知限制

- 目前只有 U1 一个战场（4 波 13 只怪、约 13 题）。扩展到 8 个单元需要逐个设计路径与塔位。
- 塔的升级只影响射程和外观（旗子、金线），**没有做伤害数值差异**——因为每只怪血量固定为 1，答对即消灭。等级的实际意义偏弱，后续可以让高级塔一次打多只。
- 拼写怪的错法只做相邻字母交换，覆盖不到"漏字母""多字母"等其他错误类型。
- 失败的敌人会进全局错题本（`S.wrong`），但还没有做"错题训练营"这个专门节点。
- 场上有敌人但没有对应类型的塔时，`tdWaitHTML()` 会直接点破"出现了 X 怪，但没有对应的塔"。这是保姆式的提示，好处是不让孩子干瞪眼，代价是少了一点自己发现的成就感。如果孩子已经玩熟，可以把这句改成中性文案。
